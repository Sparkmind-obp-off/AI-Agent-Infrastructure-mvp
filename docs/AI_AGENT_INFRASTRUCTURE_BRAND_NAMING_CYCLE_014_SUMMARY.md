## 6. Substring / Root Destruction Gate (Formalized)

Because Cycle 013 identified **substring / root collision as the dominant destruction vector**, Cycle 014 formalizes this as a permanent, mandatory pre-screen gate for every future candidate, before it may enter any shortlist consideration in any later cycle.

For every candidate string `S`, the following must be enumerated and independently probed:

1. **Exact string** `S`.
2. **Every material substring of ≥ 3 letters**, both left-anchored and right-anchored, plus interior substrings of length 4–6.
3. **Obvious morphemes** implied by hyphenation, syllable boundary, or camel-case parse.
4. **Phonetic equivalents** across at least EN, ID, ES, DE, FR, and Nordic (NO/SE/DK) phoneme sets — not spelling variants, phonetic collisions.
5. **Common word fragments** in EN and ID that could be parsed out of `S` (e.g. `from-`, `hal-`).
6. **Known technical abbreviations** in telecom, networking, ML, cryptography, and life-sciences ontologies.
7. **Political / slang encodings** including Pig-Latin, leetspeak, rhyming slang, and platform-specific evasion spellings.
8. **Surname fragments** cross-checked against at least Nordic, Slavic, Baltic, Germanic, South-Asian, and South-East-Asian diaspora surname corpora.
9. **Pharma / medical roots** including INN stem lists (`-mab`, `-nib`, `-pril`, `-vir`, `-parin`, etc.) and generic-drug morphology.
10. **Fiction / fantasy fragments** including franchise wikis, world-building wikis, and fan-fiction indices.

**Advancement rule.** A candidate cannot advance merely because the full exact string `S` is search-sparse. It must survive gates 1–10 with no unresolved hit. **Spelling variants are never permitted as rescue** (this rule survives from Cycle 012 §17 and is reasserted here).

Rescue anti-pattern (explicitly forbidden): *"the exact string is quiet, therefore ship it."* Cycle 013 destroyed both survivors by walking gates 2, 6, and 8. Future cycles must walk all ten before spending internal effort on secondary evaluation.

When a master brand is eventually locked (post-clearance or post-acquisition):
- Rename the repository via GitHub rename (with redirect).
- Publish new-brand package names alongside legacy names, deprecate legacy on a scheduled sunset.
- Update documentation site canonical URLs with 301 redirects.
- Avoid architectural coupling: no source-code type or module name may depend on the brand string.
